페이지가 만들어지는 방식.

사이트의 HTML이 어떤 원본에서 어떤 명령으로 만들어지고, 공개 사이트로 어떻게 올라가는지. 도움말 고치는 법도 여기 있다

사이트의 페이지는 손으로 쓴 것과 스크립트가 만든 것(생성물)으로 나뉜다. 고칠 때는 늘 원본을 고치고 생성 명령을 다시 돌린다.

1원본과 생성물

사이트의 HTML 대부분은 생성물이고, 고칠 것은 원본이다. 생성물을 손으로 고치면 다음 생성이 덮어쓴다.

생성물 원본 다시 만드는 명령 커밋
docs/dashboard.html TODO.md, STATE.md, README.md, docs/*.md, docs/assets/gh_index.json·evidence.json, journal/tp/, docs/playground/js/presets.js, 덱의 deck.json python3 automation/render_dashboard.py 하지 않는다. CI가 만든다
docs/assets/gh_index.json GitHub 이슈·PR(제목의 TP-XXXX) python3 automation/gh_index.py 한다
docs/slides/study-*, talk-* slides_src/<덱>/ python3 scripts/build_study_slides.py 한다
docs/slides/research-* docs/research-*.md python3 scripts/build_research_slides.py 한다
docs/slides/index.html, 첫 화면 슬라이드 갤러리 slides_src/*/deck.json build_study_slides.py가 늘 함께 쓴다 한다
docs/slides/<덱>/cover.webp 덱의 첫 장 python3 scripts/build_study_slides.py --covers 한다
docs/help/ help_src/ python scripts/build_help.py 한다
docs/assets/thumbs/ 문서에 넣은 외부 그림 python3 automation/make_thumbs.py 한다
docs/assets/figs/tpNNNN_*.webp 실험 결과 python -m scripts.make_evidence_figures 한다
docs/assets/site/(파비콘, 공유 그림) 저장소의 지형·cost·경로 python scripts/make_site_assets.py 한다
docs/playground/js/policy_weights.js, plannerd_weights.js 학습한 정책, Planner D scripts/export_playground_policy.py, scripts/export_playground_planner_d.py 한다

손으로 쓰는 것은 docs/index.html(슬라이드 갤러리 표시 사이는 빼고), docs/404.html, docs/playground/(두 가중치 파일은 빼고), 그리고 위 표의 원본들이다.

2대시보드가 만들어지는 과정

render_dashboard.py는 저장소의 원본 파일을 읽어 HTML 한 장을 만들 뿐이다. 대시보드에서 무언가를 바꾸려면 아래 원본을 고친다.

탭 읽는 원본 고치는 법
진행 현황 STATE.md. 위 요약 칸은 TODO.md와 gh_index.json 절 제목(North star distance 등)은 대시보드가 파싱하므로 그대로 둔다
TODO TODO.md, journal/tp/(TP 원장), docs/assets/gh_index.json, docs/assets/evidence.json TODO.md는 automation/todo_tool.py로만 고친다(번호 발급, 정렬, 중복 검사)
PRD docs/prd*.md 직접 고친다
아키텍처 README.md, docs/ARCHITECTURE.md 직접 고친다
리서치 docs/research-*.md, 덱 링크는 deck.json 첫 줄 <!-- doc: 이름 | 번호 -->가 문서 버튼, <!-- tab: 이름 -->가 하위 탭이다
설계 · PoC docs/design-*.md, docs/poc-*.md 직접 고친다
시뮬레이션 docs/playground/, js/presets.js 시연은 presets.js의 PRESETS에 더한다. TODO 항목의 ▶ 링크가 저절로 붙는다
  • 문서 안의 표기는 docs/WRITING.md §4를 따른다. 논문 상세는 <details markdown="1"> 토글, 수식은 $…$, 강조는 ==문장==이다.
  • 대시보드는 저장소에 커밋하지 않는다(.gitignore). 로컬에서는 ./scripts/open_dashboard.sh가 다시 만들어 연다.
  • 이슈·PR 배지를 새로 받으려면 python3 automation/gh_index.py를 먼저 돌린다.
source .venv/bin/activate
python3 automation/gh_index.py          # 이슈·PR 색인(배지)
./scripts/open_dashboard.sh             # 대시보드를 다시 만들고 연다

3슬라이드가 만들어지는 과정

덱은 장마다 HTML 조각 하나를 원본으로 두고, 스크립트가 뷰어와 PPTX로 굽는다. 굽는 데는 pip install -e ".[slides]"(python-pptx, Pillow, 그리고 python-pptx가 함께 까는 lxml)와 google-chrome이 필요하다. build_research_slides.py는 늘 둘 다 쓰고, build_study_slides.py는 --check·--pptx·--covers일 때만 쓴다.

덱 원본 명령
챕터 발표 덱, 스터디 슬라이드 slides_src/<덱>/deck.json(제목·순서·절), slides/<id>.html(한 장) python3 scripts/build_study_slides.py [덱] [--check] [--pptx] [--covers]
리서치 문서 덱 docs/research-*.md 그대로 python3 scripts/build_research_slides.py [문서] [--pptx]
  • <aside>가 발표자 노트다. 수식은 KaTeX 구분자(\(…\), $$…$$)로 쓴다.
  • --check는 헤드리스 Chrome으로 넘침, 깨진 그림, 수식 오류를 찾는다. --pptx는 늘 먼저 검사한다.
  • build_study_slides.py는 돌 때마다 전체 목록(docs/slides/index.html)과 첫 화면 갤러리를 다시 쓴다. 덱을 더했거나 첫 장을 바꿨으면 --covers로 표지도 다시 만든다.
  • 영상은 figure.video 안의 YouTube 썸네일(docs/assets/yt/<id>.webp)이다. python3 scripts/slide_media.py yt <id>가 썸네일을 만들고, 뷰어는 누르면 youtube-nocookie iframe을 그 자리에 넣는다. PPTX는 그림에 하이퍼링크를 단다.

4도움말이 만들어지는 과정

도움말은 help_src/의 Markdown 한 파일이 주제 하나이고, build_help.py가 주제 페이지와 첫 페이지를 만든다.

원본 생성물
help_src/<주제>.md docs/help/<주제>.html
모든 주제의 절 docs/help/index.html(주제 카드와 모든 주제 찾기)
help_src/help.css, help.js, ask.js docs/help/help.css, help.js, ask.js(그대로 복사)
도움말 절과 docs/research-*.md의 절 docs/assets/search_index.json(질문으로 찾기 색인, build_search_index.py. 커밋하지 않고 공개 사이트 동기화 때 만든다)

주제 파일 쓰는 법

쓰는 것 뜻
첫 줄 <!-- help: 제목 | 순서 | 한 줄 설명 --> 주제 이름, 첫 페이지의 순서, 머리말 설명
첫 ## 앞의 문단 머리말 아래의 흐린 안내
## 절 제목 {#id} 절 하나. id는 모든 주제를 통틀어 하나뿐이어야 한다
## 절 제목 {#id .rows} 찾기 때 표의 행까지 거르는 절(용어 사전)
[](#id), [](다른주제.html#id) 글자 없는 링크. 그 절의 번호로 채운다. 없는 id면 생성이 멈춘다
==문장== 절마다 가장 먼저 기억할 문장 하나
```bash 명령 블록. 복사 단추가 붙는다
```text 출력 예시. ← 뒤는 흐린 설명이 된다
4열 이상 표 폰에서 행마다 카드로 쌓인다
id가 fix이거나 -fix로 끝나는 절 첫 페이지의 '문제가 생겼을 때' 바로 가기에 오른다

주제 더하기

  1. help_src/새주제.md를 만들고 첫 줄에 머리줄을 쓴다.
  2. python scripts/build_help.py로 만든다. 첫 페이지 카드, 주제 칩, 찾기 색인이 저절로 따라온다.
  3. pytest tests/test_help.py로 생성물이 원본과 같은지 본다.
  4. 원본과 docs/help/를 함께 커밋한다.
source .venv/bin/activate
python scripts/build_help.py            # docs/help/를 다시 만든다
python scripts/build_help.py --check    # 원본과 다른 생성물이 있으면 1로 끝난다

도움말은 공개 사이트에 올라간다. 이 PC의 주소, 장치 이름, 경로는 예시 값으로 바꿔 쓴다(6절).

5공개 사이트 동기화

main에 push하면 GitHub Actions(publish-site)가 docs/를 공개 저장소로 복사해 몇 분 안에 사이트가 바뀐다. docs/, TODO.md, STATE.md, README.md, JOURNAL.md, journal/, automation/, 워크플로 파일(.github/workflows/publish-site.yml)이 바뀐 push에서 돈다. Actions 탭에서 손으로 돌릴 수도 있다.

단계 하는 일
1. 대시보드 만들기 gh_index.py로 이슈·PR 색인을, render_dashboard.py로 대시보드를 만든다
2. 복사 docs/를 공개 저장소 사본으로 옮긴다
3. 공개용 손질 automation/site_public.py가 비공개 저장소 링크를 글자로 바꾸고, 머리말과 공유 메타를 넣고, Playground에 문서 골격을 붙인다
4. 위생 검사 automation/site_lint.py가 나가면 안 되는 것을 찾는다. 걸리면 여기서 멈추고 올리지 않는다(6절)
5. 올리기 공개 저장소 travplan-site에 commit·push한다. GitHub Pages가 사이트를 다시 만든다
  • 공개 저장소를 직접 고치지 않는다. 다음 동기화가 덮어쓴다.
  • push 직후에는 브라우저와 CDN의 사본 때문에 몇 분 동안 옛 페이지가 보일 수 있다(로컬 서버와 웹 통신 9절).
  • 실행 결과는 연구 저장소의 Actions 탭에서 본다.

6위생 검사

공개 사본에 개인 정보나 비공개 정보가 하나라도 있으면 검사가 push를 막는다.

찾는 것 예
로컬 경로 홈 폴더 기준 경로, 사용자 홈 절대 경로, 디스크 파일 주소(file 스킴)
이메일 사람의 메일 주소
토큰 모양 GitHub·API 토큰, 비밀 키
사설 IP 사무실·집 안의 숫자 주소
비공개 저장소 주소 연구 저장소로 가는 링크
금지어 automation/site_lint_denylist.txt의 말
  • 금지어 목록과 오탐 허용 목록(site_lint_allowlist.txt)은 docs/ 밖에 있어 공개되지 않는다. 허용 목록은 금지어를 빼지 못한다.
  • 금지어 목록 첫 줄의 시험 문자열을 사본에 넣으면 검사가 막는다. 검사가 살아 있는지 볼 때 쓴다.
  • tests/test_site_hygiene.py는 같은 검사를 docs/ 원본에 돌린다. 그래서 docs/의 문제는 push 전에 pytest에서 먼저 걸린다.
  • README.md, STATE.md, TODO.md는 대시보드에 들어간 뒤에야 검사된다. 이 파일들의 문제는 publish-site의 위생 검사에서 처음 걸린다.
  • 도움말과 문서에는 실제 값 대신 예시 값(192.168.x.1, 203.0.113.7, <저장소 경로>)을 쓴다.
python3 automation/site_lint.py docs/help     # 폴더 하나만 검사한다

7검사

생성물이 원본과 어긋나면 대부분 pytest가 먼저 알려 주고, 다시 만드는 명령까지 말해 준다.

검사 언제 보는 것
pytest -q 늘 코드 시험과 생성물 점검(Playground CORE_VERSION, 첫 화면 갤러리, 도움말, 사이트 위생, 매일 스터디 순서)
./scripts/check_site.sh 사이트 구조나 대시보드를 바꿨을 때 공개 사본을 워크플로처럼 만들고 위생, 폰 폭 넘침, 수식, 파비콘·공유 메타·404를 표로 낸다
./scripts/check_playground.sh Playground JS를 고쳤을 때 헤드리스 Chrome으로 기본 주행과 시연의 기대 결과, 주소 왕복을 본다
python3 scripts/build_study_slides.py --check 덱을 고쳤을 때 넘침, 깨진 그림, 수식 오류
python3 scripts/slide_media.py check 덱에 영상을 넣었을 때 영상 장의 꼴, 썸네일 유무
node scripts/check_slides_viewer.mjs 슬라이드 뷰어(build_study_slides.py의 PAGE)를 고치고 덱을 다시 만든 뒤(리서치 문서 덱 포함) 헤드리스 Chrome으로 영상을 누른 뒤의 키, YouTube 전체 화면, 작은 화면의 새 탭과 막혔을 때의 그 자리 재생, 폰 폭의 아래 막대를 본다
python3 automation/tp_registry.py check TODO를 손봤을 때 TP 원장과 TODO.md가 맞는지

8문제 해결

생성물에 생긴 문제는 원본을 고치고 생성 명령을 다시 돌리면 대부분 풀린다.

증상 원인 확인 해결
고친 dashboard.html이 되돌아갔다 생성물을 손으로 고쳤다 파일 머리의 생성 표시 원본(TODO.md, docs/*.md 등)을 고치고 다시 만든다
pytest가 "첫 화면 갤러리가 deck.json과 다르다" 덱을 고치고 갤러리를 다시 만들지 않았다 실패 메시지 python3 scripts/build_study_slides.py
pytest가 "docs/help/가 help_src/와 다르다" 도움말 원본을 고치고 다시 만들지 않았다 실패 메시지의 파일 이름 python scripts/build_help.py
pytest가 CORE_VERSION을 고치라고 한다 Playground 코어 JS를 고쳤다 실패 메시지의 새 값 docs/playground/js/state.js의 CORE_VERSION을 그 값으로 바꾼다
publish-site가 위생 검사에서 멈췄다 공개 사본에 금지된 모양이 있다 Actions 로그의 파일과 줄 그 줄을 예시 값으로 바꾸고 다시 push한다
공개 사이트가 안 바뀐다 동기화가 안 끝났거나, CDN 사본이 남았다 Actions 탭, curl -sI <주소> | grep -i last-modified 몇 분 기다린 뒤 Ctrl+Shift+R
TP 칩이 "TODO에 없음"으로 나온다 원장 없이 TODO.md를 고친 브랜치를 merge했다 python3 automation/tp_registry.py check python3 automation/tp_registry.py recover

찾는 말이 이 주제에 없다. 모든 주제에서 찾기로 넓히면 도움말에 없는 말은 리서치 문서에서 찾는다. Esc로 지운다.
